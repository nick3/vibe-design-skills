# v0.1.0-rc.1 reconstruction comparison

- Validation date: 2026-07-17
- Fixture: [`tests/fixtures/reconstruction-b2b`](../../tests/fixtures/reconstruction-b2b/README.md)
- Review type: independent Agent comparison, not human design review

## Protocol

One fresh Agent received the task, six target-product evidence files, and the
current bootstrap workflow with every routed specialist Skill. A no-Skill
baseline received the identical task and evidence.

The outputs were frozen before review. Each reviewer received only:

- the task request;
- the six product-evidence files;
- anonymous Candidate A and Candidate B artifacts;
- ten 0–2 review criteria.

Reviewers could not inspect Skill source, hidden acceptance criteria, generation
history, prior candidates, prior reviews, or prior scores. The complete reusable
protocol is documented with the fixture.

## Iteration evidence

The same 598-line no-Skill baseline remained fixed. Every candidate and every
review was produced in a fresh Agent context.

| Round | Candidate size | Product/governance review | Design-system/accessibility review | Main learning |
| --- | ---: | ---: | ---: | --- |
| Initial | 1,481 lines | 18/20 vs 17/20 | 15/20 vs 18/20 | Strong traceability, but a self-authored `REVIEW.md`, procedural pseudo-authority, and repetition were unsafe. |
| Separation fix | 1,142 lines | 18/20 vs 17/20 | 16/20 vs 17/20 | Independent review and advisory/governed blocker boundaries improved; unsupported aesthetic/process rules remained. |
| Semantic/rollback fix | 1,170 lines | 18/20 vs 16/20 | 18/20 vs 15/20 | Unknown permissions, link/button and table/list/grid semantics, and per-slice rollback became material advantages; exact visual proposals still anchored review. |
| Final | 831 lines | **19/20 vs 15/20** | **20/20 vs 15/20** | Removed unsupported exact visual bindings and default author self-check, preserved single-source rules, semantic contracts, reversible migration, and reviewer separation. |

Scores from different reviewers are not treated as a single calibrated numeric
series. The important final result is that two separate reviewers preferred the
final with-Skill candidate and identified no material harmful overreach.

## Final strengths

Both final reviewers found that the Skill candidate materially improved:

- source-to-rule-to-component/pattern/template/evaluation traceability;
- preservation of unknown permission cells without inventing grants or denials;
- link/button and table/list/interactive-grid semantic boundaries;
- visual restraint when brand, tokens, typography, and approver authority are
  missing;
- per-slice migration compatibility, rollback triggers, data preservation,
  restore verification, residual-use checks, and ownership gaps;
- separation of author checks from a frozen, separately commissioned
  independent review.

The final candidate kept exact observed visual values in the audit comparison
packet and left normative mappings unresolved. It did not create `REVIEW.md` or
`SELF-CHECK.md`, did not activate proposed blockers or thresholds, and did not
turn observed viewports into support policy.

## Remaining limitations

- The final package is still 831 lines and needs normal editorial ownership once
  materialized as separate files.
- No proposed visual system was rendered or compared.
- No interaction, accessibility, browser, device, production, or rollback tool
  was actually exercised.
- Several product/domain policies and all visual/evaluation approval owners
  remain intentionally unresolved.
- The review was performed by Agents. Independent human product/UI review
  remains required for stable `v1.0`.

## Result

**PASS for the public-preview release candidate's reconstruction behavior.**

This is evidence that the current workflow improves one realistic
reconstruction case. It is not evidence that every product, platform, maturity
level, or organization will receive the same result.
